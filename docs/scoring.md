# 採点設計

10クエスト(到達点合計125点 + ボーナス6項目最大90点 + 速度ボーナス最大200点、理論上限415点)。

## 自動判定(Sysdig MCPで判定)

`scoreboard/index.html`が15秒おきにSysdig Secure MCPサーバーへ問い合わせ、以下4クエストを自動で記録する。

| クエスト | 配点 | 判定方法 |
|---|---|---|
| オンボーディング完了 | 25pt | そのクラスタから何らかのランタイムイベントが届いた時点(CSPM/Cloud Account接続は対象外。Agentレベルのイベント到達で判定) |
| 検知(Reverse Shell Detected, High) | 25pt | `ruleName = "Reverse Shell Detected"`のイベントが最初に出た時点 |
| 初動対応(ワークロード停止) | 50pt | 直近の検知イベントから一定時間(`CONTAIN_GAP_MIN`、既定12分)新規検知が無くなった時点 |
| Wave2-aをブロック | 20pt | `ruleName = "Socat Reverse Shell Detected"`の最後のイベントから一定時間経過した時点 |

## 手動判定(Slack自己申告など)

| クエスト | 配点 | 判定方法 |
|---|---|---|
| Wave2-bをブロック | 30pt | 本物の脆弱性修正(再突破できなくなったこと)を運営が確認 |
| 侵害Pod/SA/Secretを正しく報告 | 10pt | Slackへの投稿内容を正誤判定 |
| IC指名・重大度宣言 | 10pt | Slackへの投稿 |
| CIS/脆弱性修正を報告 | 10pt | Slackへの投稿 |
| Sysdig→Slack通知連携を設定 | 10pt | 実施有無 |
| インシデントレポート提出 | 25pt | 提出の有無のみを採点対象とし、内容の正誤は判定しない |

## 速度ボーナス

各クエストについて、到達した順位ごとに追加点を付与する(1位+20 / 2位+15 / 3位+10 / 4位+5 / 5位+0)。他チームとの比較は「早く到達した順」だけで決まる。

## スコアボードの実装メモ

- `scoreboard/index.html`はブラウザのlocalStorageに手動記録を保存する(チームの共有端末1台で開く想定)。
- 自動取得分は`scope_hours`で過去何時間分を検索するかを指定する。Sysdig APIの検索期間上限は336時間(14日)で、これを超えるとエラーになる。開催日からの経過日数が長くなるとスコアが反映されなくなるバグを避けるため、デフォルトで14日(API上限)まで遡るようにしている。
- Cowork(Claude)のMCPブリッジ(`window.cowork.callMcpTool`)はページ読み込み直後はまだ使えないことがあるため、使える状態になるまで短い間隔でポーリングして待つ処理が入っている。
